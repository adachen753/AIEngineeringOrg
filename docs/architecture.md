# Architecture and reliability

FastAPI owns one background worker guarded by an OS file lock. Streamlit and CLI are HTTP clients only. Node/TypeScript adapter owns SDK turn processes and stream records. SQLite WAL records workflow/task/attempt/thread mappings, messages, approvals, commit IDs and artifacts. The role result schema cannot request arbitrary scheduling or commands.

LangGraph is a single-stage transition executor. SQLite business checkpoint is the sole durable source, not a separate LangGraph saver: every completed stage atomically saves the next stage and a checkpoint event. Queued stages resume; incomplete running stages are reconciled against adapter runs and worktree HEAD/status, then conservatively interrupted. There is no automatic replay of ambiguous deliveries and no exactly-once claim. Artifacts are written before database references; a crash may leave an orphan artifact but cannot produce a false completed record.

Manager uses a persistent read-only thread. Dev uses a task thread and repairs continue that thread on a fresh candidate-based worktree. Test has an independent task thread and only accepts test changes. Test additions are committed on top of the Dev commit. Verification uses a third detached worktree at the exact candidate SHA. Git hooks are disabled for system-generated commits. No checkout, stash, reset, clean, push or merge of the user's working tree is performed.

The runner uses a fixed argument-array isolated Python bootstrap (-I -B). It imports the installed pytest before adding the target repository to import paths, so repository-local pytest.py cannot replace the test runner. It disables bytecode/cache/plugin autoload, captures collected node IDs and actual per-test outcomes, command/exit/version/log, process PID, and HEAD/status (including ignored files) before and after. Every acceptance criterion must map to executed passing node IDs; skipped or missing tests cannot pass. Polluted directories cannot pass. Only assertion failures classified with product/test evidence can enter one repair; environment, data, flaky, unknown and collection failures block. Accepted tests are retained by starting repair from the candidate commit. Existing test AST nodes cannot be changed, and collection configuration edits require human review.

Only confirmed owned process cancellation yields cancelled. Cancelling the backend during testing shield-stops the owned process tree before releasing ownership. Ambiguous termination is interrupted and retry is prohibited; unresolved attempts in ANY workflow status block further scheduling. One explicit retry is allowed for known blocked/failed execution, and one repair is allowed. Retry-specific worktree labels retain old dirty evidence rather than cleaning or reusing it. Multiple queued requests are serialized. Clients use persistent idempotency keys; a reused key with different input is rejected.

Boundary: this is not a hostile-repository sandbox. Only explicitly authorized, small, trusted local Python repositories are supported. SDK write sandbox capabilities must be confirmed; adapter must fail closed where scope enforcement is unavailable. Backend diff validation is defense in depth, not a substitute for OS permissions.
